# Position key and book interchange format

The interchange format is how opening books are shared between programs: one file, no header, a
sorted array of 16-byte records. A position is named by an 8-byte key, so a book is a position to
moves mapping that can be searched by binary search without being loaded whole.

## The file

Every record is 16 bytes, big-endian throughout, and the records are sorted ascending by key — the
moves of one position are therefore contiguous.

| Bytes | Field | |
|---|---|---|
| 0–7 | position key | see below |
| 8–9 | packed move | see below |
| 10–11 | weight | how much the book likes the move; imported as the play count |
| 12–15 | spare | four bytes the format leaves to whoever holds the file; carried through unchanged |

A file whose length is not a multiple of sixteen is corrupt and is reported with the byte count,
not silently truncated.

## The packed move

Six bits for the from square, six for the to square, four for the promotion piece. Squares are
numbered a1 = 0 to h8 = 63.

Two conventions are worth knowing before reading a move, because both look like a bug until the
position is known:

- **Castling is written as the king taking its own rook**: `e1h1`, `e1a1`, `e8h8`, `e8a8`. No legal
  move is otherwise shaped like that, so the pair says which it is, and the app turns it back into a
  real castling move on the way in and writes it back on the way out.
- **Promotion to a queen shares its code with "no promotion"** (0). A pawn reaching the last rank
  with an empty promotion field means a queen. Knight, bishop and rook are 1, 2 and 3 and carry
  themselves.

## The position key

A position's key is the XOR of one table entry for every piece on every square, plus entries for the
side to move, the castling rights, and the en-passant file. The table has 781 numbers:

| Range | Meaning |
|---|---|
| 0–767 | piece of kind `k` and colour `c` on square `s`: `64 * (2 * k + c) + s`, kinds in the order pawn, knight, bishop, rook, queen, king, colours white then black |
| 768–771 | castling rights, one bit each: white king-side, white queen-side, black king-side, black queen-side |
| 772–779 | en-passant file a–h, set only when a pawn can actually be taken en passant |
| 780 | white to move |

The numbers are not derived from anything in this repository. They are the format: two programs
agree on a book only if they agree on all 781. They are carried as a generated data file,
`chess-core/src/key_table.rs`, regenerated by `scripts/extract-key-table.py`, with provenance in
`NOTICE.md`.

## Importing is a replay, not a loop

A record says "in this position play this move", and that means nothing unless the position can be
reached. Import therefore starts at the initial position and works outwards, applying each record's
move and following the positions it reaches. A record whose position is never reached, or whose move
is not legal where it claims to be, is skipped and reported with its byte offset. Books differ
widely here: a book compiled from games is nearly closed and imports at 96%, while a recommendation
book holds positions without the moves leading to them and may import a twentieth of itself. Both
are importable; neither is a silent loss.
